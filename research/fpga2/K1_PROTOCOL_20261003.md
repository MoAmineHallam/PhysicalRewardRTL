# K1 protocol — does generated-circuit quality change with model size?

**Frozen 2026-10-03, before any K1 training, generation or Vivado run, and before
the confirmation split is drawn.**  Implements the kill test of the
[physical-quality scaling plan](PHYSICAL_SCALING_PLAN_20261003.md#8-kill-test-k1-draft-frozen-in-its-own-protocol-before-any-sft).
Code: [`scaling/k1.py`](../../scaling/k1.py), [`scaling/sft.py`](../../scaling/sft.py),
[`scaling/make_confirmation_split.py`](../../scaling/make_confirmation_split.py),
[`scaling/eda_vivado.py`](../../scaling/eda_vivado.py).  Any change after this
point is a dated amendment, written before the affected outcome is seen.

## Question

Under one supervised fine-tuning recipe, does the failure-penalized post-route
frequency of generated circuits (`F = q·μ`), or either of its parts, change with
model size beyond training-seed noise?

## Inputs

| Input | Definition |
|---|---|
| Frozen evaluator | As Gate 0: previous-project checkout matching commit `40acc78` (nine hashed files), oracle self-check `True` |
| Models | Qwen2.5-Coder **base** 0.5B, 1.5B, 3B, 7B from ModelScope (1.5B: the Gate 0 copy).  Each must have safetensors weights and a chat template.  Weight hashes in `logs/weights.sha256` on the server. |
| Corpus | `sft_corpus.jsonl` from the frozen checkout (534 oracle-verified rows, 152 designs; fir, firr, poly, iir, med, cordic; all styles).  Stop if any corpus design is in the development or confirmation split. |
| Development split | Gate 0 `gate0/dev_split.json` (20 designs).  All five of its families are evaluated. |
| Confirmation split | Drawn before `prepare` by `make_confirmation_split.py`: seed 20261003, Gate 0 dev-split designs excluded in addition to everything Gate 0 excluded, median extrapolation widths 27 and 29 added.  Hash recorded in `k1/plan.json`.  **Not used in K1** except for the leak check. |

## Training

**Recipe:** `sft_train_v2.py` unchanged:
- LoRA r=16, alpha=32, dropout 0.05 on q/k/v/o;
- completion-masked loss;
- 4 epochs, batch 1 × 16 accumulation, cosine schedule, 5% warm-up;
- BF16, as for the earlier checkpoints `student_v1_out` and `sft_qwen_out` (emulated on V100);
- maximum length 4,096 tokens.

**Seeding:** the wrapper adds only `transformers.set_seed(seed)` before LoRA
initialisation and `seed`/`data_seed` in `TrainingArguments`.

**Learning rate:** chosen per size from {5e-5, 1e-4, 2e-4}.
- The sweep trains on the corpus minus held-out validation designs. Per family
  with at least three designs, the first `round(0.15 × designs)` (at least one)
  in SHA-256 order of the design name are held out, so whole designs, not rows,
  are held out.
- Each sweep run uses seed 1.
- The rate is selected by the lowest mean completion-token NLL on the held-out
  rows; ties go to the smaller rate.
- The choice is written once to `k1/lr_choice.json` and never changed.
- The development split is never used for this choice.

**Final adapters:** trained on the full corpus with the chosen rate. Seeds:

| Size | Seeds |
|---|---|
| 0.5B | 1, 2, 3 |
| 1.5B | 1, 2, 3 |
| 3B | 1, 2 |
| 7B | 1, 2 |

**Assignment:** jobs are assigned dynamically to the four GPUs. The GPU type is
recorded in every training record and is not a factor in the analysis.

## Evaluation

As Gate 0, at FP16 with the LoRA merged:
- 24 draws per design, temperature 1.0, batch 4, generation seed 1001;
- frozen sampler and per-family token budgets;
- two oracle streams of 1,024 vectors.

Every distinct correct circuit, deduplicated by normalized RTL across all K1
runs, is implemented once with the primary flow on the server:
- Vivado 2023.1, `xc7z020clg400-1`, 5.0 ns;
- `run_ppa.run_one` with `ppa_synth.tcl`, through `scaling/eda_vivado.py run`.

If the Phase 0 calibration fails, the server is still the only flow used; that
only limits comparison with Gate 0 numbers.

## Endpoints and analysis

**Per design:** `q`, `μ` and `F` as in Gate 0.

**Per size:**
- `q` and `F`: the mean over the development designs of the seed-mean.
- `μ`: pooled over seeds, on the **common support**, meaning designs where every
  size has at least one correct draw.

**Intervals:**
- 10,000 paired bootstrap resamples, seed 20261003.
- Designs are resampled within family × regime strata.
- Training seeds are resampled with replacement within each size.
- 95% percentile intervals for every pair of sizes.

**Seed noise:** pooled within-size SD of per-seed `F`, against the SD of the four
size means.

## Decision rule

Applied in this order:

| Outcome | Condition | Action |
|---|---|---|
| Saturated | Every size has `q` ≥ 0.95 | Re-plan: harder regimes and the public slice become the primary evaluation |
| Trend | The `F(7B) − F(0.5B)` interval excludes zero, and seed-mean `F` across 0.5→1.5→3→7B moves monotonically in that direction, or has exactly one adjacent inversion whose own interval includes zero | Proceed to Phase 2 with the scaling framing |
| Ceiling | The trend rule holds for `q` (not `F`), `μ` on the common support stays within 5% of the 0.5B value at every size, and no `μ` interval excludes zero | Proceed, led by the ceiling mechanism; Phase 2 prioritises style coverage and RL |
| No signal | No interval for `q`, `μ` or `F` excludes zero, and the SD of size means is at most the within-size seed SD | Drop the scaling framing; fall back to the fidelity-transfer study (Phase 3 alone) |
| Inconclusive | Anything else | Report.  More seeds only through an amendment written before more outcomes are seen. |

Whether `μ` is flat (within 5%) is reported alongside every outcome as a
descriptive mechanism statistic.
