\section{Related Work}
\label{sec:related}

\paragraph{RTL generation and functional feedback}
VerilogEval and RTLLM established executable evaluation for natural-language to
RTL generation~\cite{liu2023verilogeval,lu2024rtllm}.  VeriGen, RTLCoder, CodeV,
and CraftRTL improve supervised generation or data construction
~\cite{thakur2024verigen,liu2024rtlcoder,zhao2024codev,liu2024craftrtl}.
VeriSeek and VeriReason introduce verification-derived feedback
~\cite{wang2024veriseek,wang2025verireason}.  These systems motivate our
correctness oracle, but correctness alone cannot rank equivalent implementations
by achievable clock.

\paragraph{Physical optimization}
RTLRewriter optimizes existing RTL through rewriting~\cite{yao2024rtlrewriter},
while recent evolutionary and agentic systems search for improved power,
performance, or area at inference time
~\cite{min2025revolution,poet2026,evolve2026,coevo2026,drrtl2026}.  PPA-RTL and
RTL-OPT contribute physically evaluated tasks and benchmarks
~\cite{ppartl2025,lu2026rtlopt}.  Our question is complementary: can training
change a generator's one-draw distribution so repeated inference-time search is
less necessary?  The perfect-selector comparison gives an optimistic upper
bound to any supervised-policy reranker because it assumes the true post-route
frequency of every draw is already known.

\paragraph{Learned rewards}
Proxy optimization can exploit errors that are small on the data distribution
but large where an optimizer concentrates probability~\cite{gao2023scaling}.
Pre-synthesis predictors are nevertheless useful because implementation is
expensive~\cite{fang2024presynthesis,ustun2020accurate,wu2022highlevel}.  We use
such a predictor only inside training.  The paper's reward-hacking analysis is a
case study of one deployed proxy and one trajectory; it is not evidence that all
learned physical rewards fail.
